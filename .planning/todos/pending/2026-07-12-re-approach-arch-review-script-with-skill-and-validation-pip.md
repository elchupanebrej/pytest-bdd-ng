## Problem

The architecture review script needs a structured re-approach with four deliverables:

1. **Project SKILL**: A reusable skill file (under `~/.config/opencode/skills/`) that describes how to use the architecture review script, so agents can invoke it correctly.

2. **Docstring skill reference**: Generated docstrings must embed a reference comment pointing to the SKILL, so agents on update know which skill to load for docstring maintenance.

3. **Docstring validation pipeline**: A two-agent pipeline where:
   - **Orchestrator** scans all `.py` files via AST, extracts docstrings, dispatches each to a subagent editor, and applies results (replace or DELETE_DOCSTRING), preserving indentation and running `python -m py_compile` for syntax safety.
   - **Validator subagent** receives `{node_name, node_type, docstring}` and strips tautologies, type descriptions, obvious mechanics, and boilerplate — keeping only domain knowledge (business logic, side effects, constraints, non-obvious algorithm choices). Returns new text or `DELETE_DOCSTRING`.

4. **Pure templates**: Autogenerated code must be a *real template*, not hardcoded boilerplate. Only fields intended for agent/human fill-in should appear; no pre-filled example text should leak into generated output.

## Solution

1. Create project SKILL file (e.g., `arch-review-docstrings.md`) under `~/.config/opencode/skills/` or `.agents/skills/`:
   - Describes the two-agent pipeline (orchestrator + validator subagent)
   - Includes the English-translated prompts for both agents
   - Documents the output format and tool usage conventions

2. Identify the docstring generation template(s) in the codebase and add a SKILL reference comment inside each generated docstring block (e.g., `@skill:arch-review-docstrings`) so that any agent updating the codebase knows to reload that skill.

3. Translate both Russian prompts (orchestrator and validator) into English as reference material for the SKILL.

4. Audit docstring templates to ensure separation of template structure from hardcoded boilerplate — replace any pre-filled example text with `{PLACEHOLDER}` markers.
