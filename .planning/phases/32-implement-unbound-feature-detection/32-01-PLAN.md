    **A4. `_scan_feature_files(features_base_dir)` function (D-13, D-14, D-15):**
    Signature: `def _scan_feature_files(features_base_dir: Path) -> set[str]`
    Returns a `set[str]` of normalized URIs for feature files found on disk, excluding those tagged @unbound.

    Algorithm:
    1. Guard: if `not features_base_dir.is_dir()`: return empty set (Pitfall 5 from RESEARCH.md)
    2. Initialize `seen: set[Path] = set()` for symlink-loop protection (Pitfall 4)
    3. Initialize `result: set[str] = set()`
    4. Iterate `features_base_dir.rglob("*")` — this recursively walks, following symlinks (D-15)
    5. For each path `p`:
       a. Symlink guard: `real = p.resolve(); if real in seen: continue; seen.add(real)`
       b. Skip directories: `if not p.is_file(): continue`
       c. Check if file is a collectible feature file: use `path.suffixes` intersection with `gherkin_suffixes.union(link_suffixes)`. Specifically: `if not any(suffix in collectible_suffixes for suffix in p.suffixes): continue` where `collectible_suffixes = gherkin_suffixes | link_suffixes` (a frozenset from Suffix enum members ".gherkin", ".feature", ".url", ".desktop", ".webloc")
       d. Shortcut resolution (D-14): if last suffix of p is in link_suffixes (.url, .desktop, .webloc), resolve to target:
          - `.url` → `target, pathtype, _ = FeatureFileModule.get_feature_pathlike_from_url_file(p)` — note the return is `(str | None, FeaturePathType, str | None)`
          - `.desktop` → `target, pathtype, _ = FeatureFileModule.get_feature_pathlike_from_desktop_file(p)` — returns `(str | None, FeaturePathType, None)`
          - `.webloc` → `target, pathtype, _ = FeatureFileModule.get_feature_pathlike_from_weblock_file(p)` — returns `(str | None, FeaturePathType, None)`
          - If target is None (resolution failed): skip this shortcut — cannot determine binding status
          - If `FeaturePathType` is URL: the URI format for collected items from URL locators is the URL string itself. Normalize to `target` as-is (URL strings from FeatureFileModule already match the collected URI format).
          - If `FeaturePathType` is PATH: normalize target using the same `"file:" + relpath` format (step 5e below)
          - Add the NORMALIZED target URI to result set (NOT the shortcut file path)
          - Continue to next path (skip tag check for shortcuts — tag belongs to target file, not shortcut)
       e. Normalize to URI format (D-02):
          - Compute relative path: `rel = Path(relpath(p, features_base_dir)).as_posix()` — the as_posix() call ensures forward slashes matching file_locator.py:599
          - URI: `f"file:{rel}"`
          - This MUST match the canonical format at `file_locator.py:599`: `uri = "file:" + rel_feature_path.as_posix()`
       f. @unbound tag check (D-08):
          - Read file content (try up to first 4096 bytes — tags appear near top of Gherkin file): `p.read_text(encoding="utf-8")` wrapped in try/except
          - If `re.search(r"@unbound\b", content)` matches → skip this file (tagged as intentionally unbound)
       g. Add normalized URI to result set

    6. Return result

    **A5. `_parse_feature_name(path)` function (D-12):**
    Signature: `def _parse_feature_name(feature_path: Path) -> str | None`
    Lazy parse for Feature name.
    - Try: read up to 4096 bytes of file, regex `r"^Feature:\s*(.+)$"` with `re.MULTILINE`. Return `match.group(1).strip()` if found.
    - Except any Exception: return None (fall back to filename-only reason per D-12)
    - PITFALL: Do NOT let parse failure silently skip the file from detection (Pitfall 5 and 6 from RESEARCH.md). This function only affects the skip message richness, not whether the file is detected.

    **A6. `_detect_unbound_features(session)` function (D-01, D-03, D-05):**
    Signature: `def _detect_unbound_features(session: Session) -> None`
    Main entry point called from `pytest_collection_finish`.

    Algorithm:
    1. xdist worker guard (Pitfall 2 from RESEARCH.md): `if hasattr(session.config, "workerinput"): return` — detection only runs on controller, not workers
    2. Resolve features_base_dir (Pitfall 1 from RESEARCH.md): `builder = ScenarioLocatorBuilder(config=session.config); features_base_dir = builder.resolve_features_base_dir(None)` — uses the EXACT same resolution as collection-time, matching feature_locator.py:557-613
    3. Scan: `scanned_uris = _scan_feature_files(features_base_dir)`
    4. Extract: `collected_uris = _extract_collected_feature_uris(session)`
    5. Diff (D-01): `unbound_uris = scanned_uris - collected_uris` — set difference, fast O(n)
    6. If unbound_uris is empty: return early (no work to do)
    7. Read severity from config (D-05):
       - `severity_cli = session.config.getoption(str(UnboundFeatures.Cli.SEVERITY_OPTION), default="skip")`
       - `severity_ini = session.config.getini(str(UnboundFeatures.Ini.SEVERITY_OPTION))`
       - `severity = severity_cli if severity_cli != "skip" else severity_ini` — CLI overrides INI when non-default
       - Ensure severity is one of `("skip", "warn", "error")`; default to `"skip"` (D-06)
    8. For each unbound URI:
       a. Extract the relative path from the URI: strip the `"file:"` prefix to get the relative path string
       b. Resolve to absolute: `feature_path = features_base_dir / rel_path`
       c. Lazy-paerse feature name: `feature_name = _parse_feature_name(feature_path)` (D-12)
       d. Create item: `UnboundFeatureItem(name=rel_path, parent=session, feature_path=rel_path, feature_name=feature_name)`
       e. Severity dispatch (D-05):
          - `"skip"`: `item.runtest()` — calls pytest.skip internally; item goes into session.items normally
          - `"warn"`: `warnings.warn(f"Unbound feature: {rel_path}")` — issue warning, then still add item
          - `"error"`: `pytest.fail(f"Unbound feature: {rel_path}")` — fail immediately
       f. Append item to `session.items`
    9. Note: for skip and warn levels, items are appended to session.items and pytest renders them as SKIPPED. For error level, pytest.fail() halts collection immediately.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem → Plugin | Feature files on disk may contain malformed content; parse attempts must not crash detection |
| CLI/Config → Plugin | INI option `bdd_unbound_features` values are constrained by `choices=["skip","warn","error"]` in addoption() |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-32-01 | Elevation of Privilege | _scan_feature_files symlink traversal | medium | mitigate | Resolve symlinks with `Path.resolve()`, track in `seen` set; verify resolved path stays within features_base_dir tree via `Path.is_relative_to(features_base_dir)`. Paths outside tree are skipped. |
| T-32-02 | Denial of Service | _scan_feature_files regex on file content | low | accept | Regex patterns `@unbound\b` and `Feature:\s*(.+)$` have no nested quantifiers — not susceptible to catastrophic backtracking. File read bounded to first 4096 bytes. |
| T-32-03 | Denial of Service | _parse_feature_name parse failure | low | mitigate | Wrap parse in broad `except Exception`; return None on failure. Never let parse failure prevent detection — fall back to filename-only reason (D-12). |
| T-32-04 | Tampering | bdd_unbound_features INI injection | low | mitigate | `addoption()` constrains to `choices=["skip","warn","error"]`; `addini()` default is `"skip"`. Unknown values fall through to default per D-06. |
| T-32-05 | Information Disclosure | Feature file content in skip reason | low | accept | Skip reason includes feature name or filename only — no step content, no scenario data. Acceptable visibility for developer workflow. |
</threat_model>
