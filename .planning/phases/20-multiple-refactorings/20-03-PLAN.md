    Per the audit from Task 1, fix all core-to-plugin compile-time dependencies using hook indirection:

    Pattern for each violation:
    1. Identify what the core module (model/steps/parser) actually NEEDS from the plugin (a type, a factory function, a registry lookup)
    2. Define a pytest-bdd hook in src/pytest_bdd/hook.py that returns what's needed. The hook has a default implementation (returning None or a sentinel) in hook.py's hookspec. Add firstresult=True so the first plugin that implements it wins.
    3. In the core module, replace the direct `from pytest_bdd.plugin.xxx import YYY` with a call to `config.hook.pytest_bdd_xxx(...)` (or equivalent hook invocation)
    4. In the plugin (e.g., pickle_runner/hook.py), implement the hook to return the needed value

    Example for model→pickle_runner:
    - hook.py: add `pytest_bdd_get_step_dispatcher` hookspec (may already exist — check)
    - model/scenario_run.py: replace `from pytest_bdd.plugin.pickle_runner.plugin import _step_dispatcher` with hook call
    - plugin/pickle_runner/hook.py: implement the hook to return the dispatcher

    Example for parser→struct_bdd:
    - hook.py: add `pytest_bdd_get_struct_bdd_parser` hookspec
    - parser.py: replace struct_bdd import with hook call
    - plugin/struct_bdd/hook.py: implement the hook

    CRITICAL: This is PURE RESTRUCTURING. Zero behavior change. All hook implementations must produce identical runtime behavior. The hook indirection must be transparent to callers — same return values, same error handling.

    After fixes, verify with layer_rules.py from Plan 01: `uv run python -m pytest_bdd._ruff.rules.layer_rules src/pytest_bdd/`

| Boundary | Description |
|----------|-------------|
| pytest11 entry points → pytest runtime | Plugin code loaded at pytest startup; malicious plugin could hijack test execution |
| hooks → plugin implementations | Hook indirection adds indirection layer; hook implementation order affects behavior |
| optional-dependencies → pip install | User controls which extras are installed; missing extras cause ImportError |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-20-10 | Information Disclosure | Plugin audit report | accept | Audit report contains only architecture metadata; no secrets or user data |
