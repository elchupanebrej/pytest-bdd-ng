    **Guide 03: Parallel Execution with xdist (03-parallel-execution-xdist.md)**

    Problem: User has 500+ Gherkin scenarios and tests take too long sequentially. They need parallel execution across CPU cores.

    Solution structure:
    1. Install pytest-xdist: pip install pytest-xdist
    2. Configure pytest-bdd for xdist: worker synchronization via gherkin_message_reporter
    3. Understand what IS parallelized (scenarios) and what is NOT (feature file collection)
    4. Use test group ordering with xdist: semantic groups, xdist barrier sync
    5. CI configuration: -n auto, load balancing strategies

    Complete example: Run 200 scenarios across 8 workers with test group ordering and verify that reporting (Cucumber JSON, JUnit) remains coherent.

    Common mistakes:
    - Expecting features to be parallelized (features are collected sequentially; only scenarios run in parallel)
    - Not configuring xdist barrier sync (duplicate step registration across workers)
    - File-locking issues with formatter output files (use worker-specific filenames)

    **Guide 05: Migration from pytest-bdd v1 (05-migration-from-v1.md)**

    Problem: User is migrating from pytest-bdd (original, unmaintained) to pytest-bdd-ng. Need to understand breaking changes and migration path.

    Solution structure:
    1. Why migrate: active maintenance, mypy --strict typing, Go parser, Cucumber Messages protocol, plugin architecture
    2. Breaking changes checklist:
       - Fixture injection: pytest-bdd-ng uses explicit fixture names, not argument-name matching
       - Hooks: pytest-bdd-ng has more granular hooks (before/after/around marks AND tags)
       - Configuration: some ini options renamed or restructured
       - CLI flags: --cucumberjson removed (use --cucumber-json instead); new flags added
       - Step parser behavior: heuristic parser priority order differs
       - Plugin loading: core/extra split means some plugins require explicit extra install
    3. Migration steps (step-by-step):
       a. Install pytest-bdd-ng and uninstall pytest-bdd
       b. Update imports: `from pytest_bdd import ...` (same import path, but verify)
       c. Update fixture injection: review step definitions for fixture name mismatches
       d. Update hooks: migrate before/after_scenario → pytest_bdd_before_scenario/after_scenario
       e. Run test suite, fix step matching errors
       f. Enable new features: Go parser, struct BDD, custom formatters
    4. Complete example: Before/after comparison of a full test file with 3 scenarios, showing the exact changes needed.

    Common mistakes:
    - Forgetting to install extras (formatters, struct-bdd) — leads to missing plugin errors
    - Assuming fixture injection works the same way (argument names no longer auto-match fixture names)
    - Not updating CI configs to use the new plugin names in pytest.ini
