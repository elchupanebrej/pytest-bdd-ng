<objective>
Add a `collect-failed-logs` downstream job to `.github/workflows/main.yml` that fires when any matrix cell in `test` or `test-xdist-remote` fails, downloads raw step output for every failed cell via `actions/github-script@v7` (Octokit REST API), prepends a metadata header to each log file, and bundles them as a single `actions/upload-artifact@v4` artifact.

Purpose: Eliminate manual GitHub Actions UI inspection for failed CI runs. One artifact download provides grep-able logs for all failed cells with self-contained metadata (job name, run URL, timestamp). No changes to the hot path — existing `test` and `test-xdist-remote` jobs run unchanged.
Output: Modified `.github/workflows/main.yml` with a new `collect-failed-logs` job appended after `test-xdist-remote`.
</objective>

Append a new `collect-failed-logs` job definition to the end of `.github/workflows/main.yml` (after the `test-xdist-remote` job, separated by a blank line). The job uses two GitHub-owned actions — `actions/github-script@v7` and `actions/upload-artifact@v4` — with no checkout, no language setup, and no project dependencies.

**Job header:**
- `runs-on: ubuntu-latest` with two-space indent under job key (matches existing `test-xdist-remote` pattern, PATTERNS.md §A lines 87-98).
- `permissions: { actions: read, contents: read }` with four-space indent (per D-06; new pattern — no existing per-job permissions block in codebase, PATTERNS.md §Permissions Pattern).
- `needs: [test, test-xdist-remote]` with four-space indent (per D-01; new syntax — no existing `needs` usage, but standard GHA).
- `if: failure()` with four-space indent (per design spec §New job; new syntax — no existing `failure()` usage in codebase).

**Step 1 — github-script:**
Use `actions/github-script@v7` with a `script:` block containing the inline JavaScript. The script body:

1. Requires `node:fs` and `node:path` (stdlib, no npm packages).
2. Destructures `context.repo` for `owner`/`repo`, builds `runUrl` from template literal `https://github.com/${owner}/${repo}/actions/runs/${context.runId}`.
3. Calls `github.rest.actions.listJobsForWorkflowRun({ owner, repo, run_id: context.runId, per_page: 100 })` to enumerate all jobs.
4. Filters `data.jobs` to entries where `conclusion === 'failure'` AND `name !== 'collect-failed-logs'` (defensive self-exclusion per D-03).
5. If no failed jobs found, calls `core.info('No failed jobs found.')` and returns early.
6. Creates `failed-job-logs/` directory via `fs.mkdirSync(..., { recursive: true })`.
7. Iterates each failed job:
   - Sanitizes `job.name` via `.replace(/[^A-Za-z0-9._-]/g, '_')` (per D-04).
   - Inside a try/catch block (per D-07), calls `github.rest.actions.downloadJobLogsForWorkflowRun({ owner, repo, job_id: job.id })`, receives `log` response.
   - Builds metadata header array and writes file:
     ```javascript
     // Per D-02: metadata header written to file content (not core.info)
     // for self-contained offline artifact per RESEARCH.md recommendation
     const header = [
       `Job: ${job.name}`,
       `Run:  ${runUrl}`,
       `At:   ${new Date().toISOString()}`,
       ''
     ].join('\n');
     fs.writeFileSync(filePath, header + log.data);
     ```
   - In the catch, calls `core.warning(...)` with job name and error message, continues loop.
8. After loop, calls `core.info(...)` with download count summary.

**Step 2 — upload-artifact:**
Use `actions/upload-artifact@v4` (matches existing pattern in `messages-baseline-drift.yml` lines 83-88, PATTERNS.md §B):
- Step-level `if: hashFiles('failed-job-logs/*.log') != ''` guard (per D-08).
- `with: name:` set to `failed-job-logs-run-${{ github.run_number }}-attempt-${{ github.run_attempt }}` (per D-05; includes `run_attempt` to avoid collision on re-runs, RESEARCH.md §Pitfall 1).
- `with: path:` set to `failed-job-logs/`.
- `with: if-no-files-found:` set to `ignore` (per D-08).

**YAML formatting rules (from PATTERNS.md):**
- Two-space indent on the job key; four-space indent on properties inside the job.
- Step names use `- name: {human-readable}` with dash-space-name colon-space convention.
- Pinned action versions: `@v7`, `@v4` (no floating tags).
- Blank line before the new job for separation from `test-xdist-remote`.

**Do NOT:** modify any existing job (`test` or `test-xdist-remote`), add `actions/checkout`, add `tee` or per-step wrapping in the hot path, use `core.info` for the metadata header (write to file content instead, RESEARCH.md §Architecture Patterns recommendation), hardcode the repository name (use `context.repo`), omit `per_page: 100`, omit `run_attempt` from the artifact name.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GHA Runner → GitHub REST API | `GITHUB_TOKEN` authenticates Octokit calls to `listJobsForWorkflowRun` and `downloadJobLogsForWorkflowRun`. Read-only context — token has `actions:read, contents:read` scopes only. |
| GHA Runner filesystem → Artifact storage | `actions/upload-artifact@v4` zips `failed-job-logs/` and uploads to workflow run storage. Artifact is publicly accessible to repo members with read access. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-01 | Information Disclosure | `collect-failed-logs` job — `GITHUB_TOKEN` exposure via debug logging | low | mitigate | `permissions: { actions: read, contents: read }` is least-privilege (D-06). Token is auto-expiring and scoped to current repo only. No `secrets` or write tokens referenced. |
| T-33-02 | Information Disclosure | Artifact contents — step output in downloadable ZIP | low | accept | Artifact contains only step output already visible in the GitHub Actions UI, plus job name/run URL/timestamp metadata. No new secrets or sensitive data are introduced. This is a public CI log — disclosure risk is inherent to the design goal. |
| T-33-03 | Tampering | `actions/github-script@v7` — script injection via untrusted input | low | mitigate | No `workflow_dispatch` inputs accepted by this workflow. No expression interpolation from untrusted sources into the inline script body. The script uses only `context` properties (GitHub-provided) and API responses (authenticated). |
| T-33-04 | Denial of Service | GitHub REST API — rate limit exhaustion from many log downloads | low | accept | Maximum ~21 failed cells (18 test matrix + 3 xdist-remote modes) per run. `per_page: 100` minimizes pagination calls. GitHub's per-repo rate limit for `GITHUB_TOKEN` is 1,000 req/hr — this is well within limits. Per-job try/catch (D-07) gracefully handles individual failures if throttling occurs. |
</threat_model>
