## Phase 5 - Wave 2: Steps Tests

**Objective:** Achieve >80% line coverage on `steps.py` (760 lines).
This requires testdir-based integration tests (steps.py is coupled to pytest
runtime for decorator registration, fixture injection, and step matching).
Create `tests/unit/test_steps.py` covering step decorators, matcher priority,
registry hierarchy, fixture injection, and the Definition class. Also add a
standalone test for ContextErrorState.

**Why this matters:** `steps.py` has the highest support burden for step matching
failures (D-01). It has zero dedicated unit tests today — only indirect coverage
from feature tests. Testdir-based tests are the only viable approach since step
decorators require a live pytest runtime.

**Output:** `tests/unit/test_steps.py` with testdir-based tests (tagged
`@pytest.mark.unit`), `tests/unit/test_context_error_state.py` with direct tests.

## Trust Boundaries

- testdir subprocess — Testdir spawns a subprocess pytest run. Tests must not rely on shared mutable state between conftest and test file.
- Step registry isolation — Each testdir test runs in isolated subprocess; registries are automatically isolated.
- Matcher test correctness — Matcher tests need realistic FixtureRequest mock — testdir ensures real pytest infrastructure.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-05-07 | Denial of Service | **testdir overhead** | accept | Acceptable for 20-30 steps.py tests; model tests use direct instantiation. |
| T-05-08 | Tampering | **Step registry pollution** | mitigate | Each testdir test runs isolated subprocess; no cross-test pollution. |
</threat_model>
