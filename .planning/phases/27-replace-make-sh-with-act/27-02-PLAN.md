# Plan 2: Close Workflow and Script Evidence Findings

## Goal

Convert the review findings from the Phase 27 artifact-BDD pass into an executable wave. The phase must prove the
local workflow targets, CI workflow boundary, script command surface, artifact naming, and test-code quality rules
without relying on vague claims or tool-branded artifact names.

## Context

The first Phase 27 plan replaced Make and shell wrappers with local workflow targets and Python scripts. Review later
found several gaps:

- CI workflows were treated as deleted even though GitHub Actions still needs `main.yml` and `release.yaml`.
- Local artifact paths used `act` in runtime artifact names, which makes the runner tool look like the product surface.
- Workflow report creation used embedded Python heredocs for static JSON that can be written directly by the shell.
- The claim that all files in `scripts/` had BDD/ATDD coverage was false.
- Contract tests touched in this phase used bare `assert` and local lint suppressions even though PyHamcrest is the
  intended assertion style.

This wave closes those gaps without expanding the target beyond Phase 27's purpose: every development command surface
that replaces Make or shell must be covered by executable BDD/ATDD evidence, and every helper under `scripts/` must be
either covered directly or explicitly documented as private behind a covered facade.

## Tasks

### Task 1: Restore and classify workflow ownership

**Files:** `.github/workflows/{main.yml,release.yaml,messages-baseline-drift.yml,docs.yml,env.yml,lint.yml,tests.yml,release.yml`

1. Restore `main.yml` as the GitHub-hosted compatibility and remote-test CI gate.
2. Restore `release.yaml` as the GitHub release publishing workflow.
3. Add short comments to every workflow explaining whether it is CI-owned or a local/manual artifact target.
4. Ensure local artifact workflows are manual/local unless intentionally promoted to CI.
5. Ensure local release artifact workflow does not publish packages; package upload remains in `release.yaml`.

**Acceptance Criteria:**

- [ ] `.github/workflows/main.yml` exists and contains the Python/OS tox matrix plus xdist-remote modes.
- [ ] `.github/workflows/release.yaml` exists and publishes only on GitHub release creation.
- [ ] Every workflow file starts with a CI/local ownership comment.
- [ ] Local artifact workflows use `workflow_dispatch` only unless a CI promotion is explicitly documented.
- [ ] Contract tests prove CI workflows are present and local workflows are not described as replacements for CI gates.

### Task 2: Rename local artifact paths away from runner tooling

**Files:** local workflows, `features/18 Development/*.feature.md`, E2E step harness, docs feature copies, contract tests

1. Replace `.tmp/act-artifacts/...` with a neutral runtime artifact root such as `.tmp/local-artifacts/...`.
2. Rename the BDD cleanup step from `clean repository Act artifacts` to `clean repository local artifacts`.
3. Keep the runner tool only in command execution steps and workflow comments where it describes how local workflows run.
4. Update all artifact assertions and reports to the neutral artifact root.

**Acceptance Criteria:**

- [ ] No local runtime artifact path contains `act`.
- [ ] `rg -n "act-artifacts|Act artifacts|clean repository Act artifacts"` returns no matches in workflow, feature,
  contract, and E2E harness files.
- [ ] Real local workflow BDD scenarios assert artifacts under `.tmp/local-artifacts/...`.

### Task 3: Replace embedded Python report writers with direct file creation

**Files:** `.github/workflows/{docs,env,lint,tests,release}.yml`

1. Replace static `python - <<'PY'` JSON report writers with direct shell file creation.
2. Preserve dynamic environment report fields with shell variables before writing JSON.
3. Keep Python only where it is the actual tool under test or command under orchestration, not as formatting glue.

**Acceptance Criteria:**

- [ ] Local artifact workflows contain no embedded Python heredocs solely for static JSON report writing.
- [ ] Report JSON remains parseable and keeps the fields asserted by BDD.
- [ ] Release report still proves wheel and source archive expectations through artifact directory assertions.

### Task 4: Create a complete `scripts/` BDD/ATDD coverage inventory

**Files:** `features/18 Development/`, `src/pytest_bdd_testing/case/e2e/feature/test_18_development.py`,
`src/pytest_bdd_testing/case/contract/test_python_scripts.py`

1. Generate an explicit inventory of every file under `scripts/`.
2. For each script, classify it as one of:
   - directly covered executable script target;
   - covered through a facade command such as `scripts/arch.py`;
   - private implementation helper behind a covered facade;
   - uncovered gap requiring a new BDD/ATDD scenario.
3. Add BDD/ATDD scenarios for every uncovered direct script or facade command.
4. For private helpers, add contract evidence that names the facade that imports or delegates to the helper.
5. Ensure `docs_build.py` is proven as the implementation behind the docs build target, not only as static AST text.

**Acceptance Criteria:**

- [ ] Every current file from `rg --files scripts` appears in a script coverage inventory.
- [ ] No script remains in an ambiguous "mentioned but not covered" state.
- [ ] Direct scripts have executable BDD/ATDD scenarios with command construction through tables or docstring-backed
  command steps, not long inline shell snippets.
- [ ] Facade-covered helpers have contract tests that prove the facade command delegates to the helper.
- [ ] `scripts/docs_build.py` is invoked by the docs workflow or an equivalent covered facade.

### Task 5: Bring touched contract tests under the project test-style rules

**Files:** `src/pytest_bdd_testing/case/contract/test_act_workflows.py`,
`src/pytest_bdd_testing/case/contract/test_python_scripts.py`, `DEVELOPMENT.rst`

1. Replace bare `assert` statements in touched Phase 27 contract tests with PyHamcrest `assert_that`.
2. Remove `# pylint: disable=S101` and equivalent local suppressions introduced only to silence bare-assert checks.
3. Keep tests as module-level functions, not `class Test*` containers.
4. Ensure `DEVELOPMENT.rst` records the rule and no duplicate guidance is added to `AGENTS.md`.

**Acceptance Criteria:**

- [ ] `rg -n "assert .*#.*S101|pylint: disable=S101" src/pytest_bdd_testing/case/contract/test_act_workflows.py src/pytest_bdd_testing/case/contract/test_python_scripts.py` returns no matches.
- [ ] `rg -n "^class Test" src/pytest_bdd_testing/case/contract/test_act_workflows.py src/pytest_bdd_testing/case/contract/test_python_scripts.py` returns no matches.
- [ ] Focused contract tests pass.

## must_haves

### truths

- CI workflows and local artifact workflows have separate ownership and comments.
- Runtime artifacts use neutral names that describe the artifact role, not the runner tool.
- Static JSON report files are written directly by workflow shell steps.
- Every `scripts/` file is explicitly covered directly, covered through a facade, or classified as private behind a
  covered facade.
- Touched Phase 27 contract tests use PyHamcrest and module-level test functions.

### prohibitions

- Do not delete `main.yml` or `release.yaml` as part of local workflow migration.
- Do not use `act` in local artifact directory names.
- Do not add bare-assert suppressions to Phase 27 tests.
- Do not claim all scripts are covered unless the inventory proves each file's route.

## Artifacts this wave produces

- Script coverage inventory and BDD/ATDD scenarios for uncovered script command surfaces.
- Updated local workflow artifacts under `.tmp/local-artifacts/...`.
- Restored CI workflow files with ownership comments.
- PyHamcrest-compliant Phase 27 contract tests.
