    Implement build_step_tree in step_tree.py (PATTERNS.md lines 480-508). This is the hardest mapping per RESEARCH.md. The function receives a `list[ExecutionProjection]` for a single test case (pre-grouped by collector) and returns `tuple[list[AllureStepResult], list[AllureStepResult]]` where first list = regular steps, second list = hooks/background steps (for befores on TestResult).

    Algorithm (stack-based, per RESEARCH.md lines 330-335):
    1. Maintain two stacks: `regular_stack: list[AllureStepResult]` (for current nesting depth) and `regular_roots: list[AllureStepResult]` (top-level regular steps). Same for hooks: `hook_stack` + `hook_roots`.
    2. Iterate projections chronologically (they arrive in order from reader).
    3. On TestStepStarted (payload_kind == "test_step_started"):
       - Extract step name from projection payload (check `.stepDefinitionId` or `.pickleStepId` for lookup; fallback to using payload's string representation or ID).
       - Determine if this is a hook step: check if payload has `hook_id` attribute (background steps and hooks carry this).
       - Create an AllureStepResult(name=step_name, status="unknown", start=timestamp_from_projection).
       - If hook → push to hook_stack or hook_roots (if stack empty).
       - Else → push to regular_stack; if regular_stack has items, this step goes as child of stack[-1].steps; else to regular_roots.
    4. On TestStepFinished (payload_kind == "test_step_finished"):
       - Match to corresponding started step via `testStepId` from both Started and Finished payloads.
       - Set status from Finished payload's `testStepResult.status` (map: "PASSED"→"passed", "FAILED"→"failed", "SKIPPED"→"skipped", "UNDEFINED"→"broken").
       - Set stop = timestamp from Finished payload (convert seconds/nanos to millis: `seconds*1000 + nanos//1000000`).
       - Pop from appropriate stack (hook or regular).
    5. Return `(regular_roots, hook_roots)`.

    Status mapping: cucumber-messages TestStepResult.Status enum values → Allure status strings. Use a dict constant at module level: `_STATUS_MAP = {"PASSED": "passed", "FAILED": "failed", "SKIPPED": "skipped", "UNDEFINED": "broken", "PENDING": "skipped", "AMBIGUOUS": "broken"}`.
    Timestamp conversion: cucumber_messages.Timestamp has seconds (int) and nanos (int) → convert to milliseconds (int). Helper function `_timestamp_to_ms(ts) -> int`.

    Import: `AllureStepResult` from `.model`, `ExecutionProjection` from adapter, `PayloadKind` from message_extension, `attrs` if needed. Use `from __future__ import annotations`. No bare `return None` — return `([], [])` for empty. Handle unknown payload_kind gracefully (skip, don't crash).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NDJSON file → reader | External NDJSON input parsed with json.loads — untrusted JSON crosses here |
| converter output → disk | Allure JSON written to filesystem at user-specified output_dir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-03 | Spoofing | reader.py read_envelopes | mitigate | Validate NDJSON line parses as JSON before deserialize; raise ValueError with context on malformed input (not bare Exception) |
| T-20-04 | Denial of Service | reader.py read_envelopes | mitigate | Stream NDJSON line-by-line (not read all into memory); ExecutionMessageAdapter already supports this pattern |
| T-20-05 | Tampering | emitter.py emit_results | mitigate | Use UUID-based filenames for output (not user-controlled); output_dir created with mkdir parents |
| T-20-06 | Information Disclosure | step_tree.py, mapper.py | accept | No PII processed in cucumber message conversion; event metadata is test structure only |

</threat_model>
