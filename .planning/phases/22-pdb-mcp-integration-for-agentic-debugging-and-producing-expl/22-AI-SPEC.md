## 1. System Classification

**System Type:** Code Automation / Autonomous Debugging Assistant Integration

**Description:**
Phase 22 adds an agent-facing debug channel for pytest and pytest-bdd-ng. When a test fails under `--mcp-pdb-on-fail`, pytest exposes the live failed process through `mcp-pdb` so a coding agent can inspect stack frames, locals, fixtures, BDD runtime metadata, and PDB state before deciding what investigation artifact to write. Good behavior means the agent can attach predictably, inspect the real failure state without reimplementing a debugger, release the held test safely, and leave Markdown/JSON artifacts useful to humans and later automation.

**Critical Failure Modes:**

1. A failed test process hangs indefinitely because no MCP client connects or a connected client stops heartbeating.
2. Debug state exposed to the agent is stale, mismatched to the active failure, or points at the wrong pytest nodeid.
3. The plugin reimplements PDB/MCP behavior instead of depending on `mcp-pdb`, creating drift and extra attack surface.
4. BDD metadata or artifacts are attached to the wrong scenario, step, example row, or run.
5. Debugger access leaks beyond trusted local development assumptions or binds to an unsafe interface by default.

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Developer tooling / test automation

**User Population:** Coding agents, babysitting agents, and human maintainers debugging pytest or pytest-bdd-ng failures during local development and controlled CI-style runs.

**Stakes Level:** High

**Output Consequence:** Agent observations drive code changes, test triage, and BDD run artifacts. Incorrect state, missing cleanup, or misleading artifacts can waste developer time, mask real failures, or cause unsafe debugger exposure.

### What Domain Experts Evaluate Against

| Dimension | Good (expert accepts) | Bad (expert flags) | Stakes | Source |
|-----------|-----------------------|--------------------|--------|--------|
| Failure-state fidelity | Active queue entry, PDB frame, nodeid, and BDD metadata describe the same failing test | Agent inspects a previous failure, controller state, or unrelated frame | High | pytest debugging practice, pytest-bdd-ng runtime model |
| Debug lifecycle safety | No-client timeout, heartbeat lease, release, and raw PDB continue all resume pytest deterministically | Test run hangs, double-resumes, or leaves socket/session files stale | High | Phase 22 exploration decisions |
| Dependency boundary | `mcp-pdb` owns PDB/MCP primitives; pytest-bdd-ng owns orchestration, metadata, and artifacts | Local code duplicates debugger server commands or diverges from `mcp-pdb` semantics | Medium | mcp-pdb README/API |
| Artifact usefulness | Markdown states finding, evidence inspected, suspected cause, and next action; JSON mirrors machine fields | Artifact is transcript noise, missing nodeid/step, or not linkable to BDD run | Medium | BDD artifact workflow |

### Known Failure Modes in This Domain

- Debugger server waits forever in non-interactive runs.
- Fixed port conflicts fail late or connect agent to another stale process.
- xdist or repeated failures confuse active-failure ownership; Phase 22 v1 uses a single queue to avoid this.
- Agent sends `continue` while plugin expects a release command, or release command races raw PDB continuation.
- Artifact writer captures broad locals or secrets unnecessarily instead of agent-curated findings.
- BDD enrichment runs after failure state is cleared, losing current feature/scenario/step context.

### Regulatory / Compliance Context

No external regulatory regime identified for this internal developer-tooling feature. Security constraint is explicit: `mcp-pdb` can execute Python through PDB, so support only trusted environments by default and document that remote/public binding is unsafe unless deliberately configured.

## 2. Framework Decision

**Selected Framework:** `mcp-pdb`

**Version:** Pin `mcp-pdb>=0.6.0,<0.7` in optional extra for Phase 22 planning; verify exact lower bound during implementation against import/API needs.

**Rationale:**
`mcp-pdb` is purpose-built for exposing Python PDB to LLM agents through MCP. It already provides local and remote debug tools such as `connect_remote_debug`, `send_pdb_command`, breakpoint management, variable examination, status, restart, and end-debug operations. Its `rpdb` mode supports a remote PDB socket and documented pytest usage via `pytest --pdb --pdbcls=mcp_pdb.rpdb:Debugger` on Python 3.11+, plus `mcp_pdb.rpdb.set_trace()` for direct in-process breaks. Phase 22 should compose this functionality rather than implementing a debugger/MCP server from scratch.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Custom MCP PDB implementation | Reimplements debugger protocol, socket handling, command routing, and MCP tool surface that `mcp-pdb` already provides |
| `remote-pdb` only | Provides remote PDB transport but no MCP tool layer for agents |
| Plain pytest `--pdb` | Human-terminal oriented, no agent discovery, heartbeat, artifact, or BDD metadata contract |
| LangGraph / CrewAI / OpenAI Agents SDK | Orchestrate agents, but this phase builds debugger integration primitives, not an agent workflow runtime |

**Vendor Lock-In Accepted:** Partial — depends on open-source `mcp-pdb` and MCP protocol conventions, but keeps adapter boundary narrow so the plain pytest layer can later become a separate plugin.

## 3. Framework Quick Reference

> Fetched from official docs by `gsd-ai-researcher`. Distilled for this specific use case.

### Installation

```bash
uv add --optional debug-mcp "mcp-pdb>=0.6.0,<0.7"
```

### Core Imports

```python
from mcp_pdb.rpdb import Debugger, set_trace
```

Implementation must verify whether the MCP server tool functions are importable as stable public APIs. If not, use `mcp-pdb` as an external server/runtime and keep pytest-bdd-ng integration in an adapter that drives documented entry points.

### Entry Point Pattern

```python
def pytest_addoption(parser):
    group = parser.getgroup("mcp-pdb")
    group.addoption("--mcp-pdb-on-fail", action="store_true")
    group.addoption("--mcp-pdb-host", default=None)
    group.addoption("--mcp-pdb-port", type=int, default=None)
    group.addoption("--mcp-pdb-timeout", type=float, default=None)
    group.addoption("--mcp-pdb-lease", type=float, default=None)
    group.addoption("--mcp-pdb-artifacts", default=None)


def pytest_sessionstart(session):
    state = DebugMcpState.from_config(session.config)
    if state.enabled:
        state.start_session()
        state.write_discovery_file(status="waiting_for_failure")


def pytest_runtest_makereport(item, call):
    if call.excinfo is None or call.when != "call":
        return

    state = DebugMcpState.from_config(item.config)
    if not state.enabled:
        return

    failure = QueuedFailure.from_item_and_call(item, call)
    state.queue.hold_one(failure)
    state.adapter.enter_pdb_for_failure(failure)
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `mcp-pdb` MCP server | Agent-facing tool server for PDB commands | Agent connects and sends debugger commands |
| `rpdb` / remote PDB | Python process exposing PDB over TCP | Failed pytest process needs live inspection |
| Failure queue | Single active failed test waiting for agent attach/release | Prevent multiple failures from racing shared PDB state |
| Heartbeat lease | Connected-client liveness contract | Avoid stuck sessions when agent dies |
| Discovery file | `.pytest_cache/mcp-pdb/session.json` | Let babysitter/debug agent find host, port, and active failure |
| BDD adapter | pytest-bdd-ng metadata bridge | Enrich plain pytest failures with feature/scenario/step context |
| Artifact sink | Markdown/JSON investigation writer | Store agent-curated findings, then bridge to BDD artifact hook |

### Common Pitfalls

1. `mcp-pdb` can execute Python through PDB; never enable broad remote binding by default.
2. `rpdb` defaults may block waiting for a client; Phase 22 must own no-client timeout and heartbeat cleanup explicitly.
3. Fixed ports can collide; when no port is configured, allocate a free port and publish it through session discovery.
4. pytest report hooks have phase-specific behavior; only failed call/setup phases intended for debugging should enqueue.
5. BDD runtime context may live in pytest stash; capture metadata before cleanup hooks clear it.

### Recommended Project Structure

```text
src/pytest_bdd/plugin/debug_mcp/
├── __init__.py
├── entrypoint.py          # plugin factory / registration
├── hook.py                # pytest hooks, thin adapter
├── options.py             # CLI + ini parsing
├── queue.py               # single active failure, timeout, lease
├── discovery.py           # session.json + terminal line
├── mcp_pdb_adapter.py     # all mcp-pdb imports and runtime calls
├── artifacts.py           # plain pytest Markdown/JSON sink
└── bdd_adapter.py         # BDD metadata + artifact hook bridge
```

## 4. Implementation Guidance

**Model Configuration:**
No model calls are made by pytest-bdd-ng. Agent model selection belongs to external Codex/Claude/babysitter orchestration. The plugin exposes deterministic state and artifact contracts only.

**Core Pattern:**
Build a pytest-only plugin first. It starts session discovery, enqueues one failed test, enters/attaches remote PDB via `mcp-pdb`, and resumes via explicit release, raw PDB continue, timeout, or heartbeat expiry. Add pytest-bdd-ng enrichment as a second adapter layer.

**Tool Use:**
Use `mcp-pdb` tools for PDB commands and variable inspection. Add only pytest-bdd-ng-specific tools/primitives if they are not expressible as PDB inspection: current BDD metadata, artifact write/release helpers, and queue state.

**State Management:**
Store run/session state in pytest `Config.stash` through established `StashBound` patterns. Persist only discovery and artifact files:

- `.pytest_cache/mcp-pdb/session.json`
- configurable artifact root, default `.pytest_cache/mcp-pdb/artifacts/{run_id}/`

**Context Window Strategy:**
Do not dump locals, transcripts, or full stack into artifacts automatically. Give the agent live PDB access and require it to curate compact Markdown/JSON findings with nodeid, BDD metadata, inspected evidence, suspected cause, and next action.

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice.

### Structured Outputs with Pydantic

Use Pydantic models for session discovery and investigation artifacts. Validate before writing JSON; Markdown can be generated from the validated model.

```python
from pathlib import Path
from typing import Literal

from pydantic import BaseModel, Field


class BddMetadata(BaseModel):
    feature_path: str | None = None
    feature_name: str | None = None
    scenario_name: str | None = None
    step_keyword: str | None = None
    step_text: str | None = None
    tags: list[str] = Field(default_factory=list)
    example_row: dict[str, str] = Field(default_factory=dict)


class ActiveFailure(BaseModel):
    nodeid: str
    exception_type: str
    message: str
    bdd: BddMetadata | None = None


class SessionDiscovery(BaseModel):
    host: str
    port: int
    session_id: str
    status: Literal["waiting_for_failure", "holding_failure", "connected", "closed"]
    active_failure: ActiveFailure | None = None


class InvestigationArtifact(BaseModel):
    nodeid: str
    status: Literal["root_cause_found", "needs_more_info", "released_without_finding"]
    summary: str
    inspected_evidence: list[str]
    suspected_cause: str | None = None
    next_action: str
    markdown_path: Path
    json_path: Path
```

### Async-First Design

pytest hook bodies should stay synchronous and thin. Any heartbeat server, lease watcher, or socket wait must run in bounded background primitives with deterministic shutdown in `pytest_sessionfinish`. Avoid blocking pytest hook calls except for the explicit configured failure hold.

### Prompt Engineering Discipline

This plugin should not embed broad prompts. If an artifact template is provided for agents, keep it declarative:

- inspect live state first;
- cite exact PDB commands/evidence;
- write concise Markdown/JSON;
- release the failure when done.

### Context Window Management

Agent-facing state should be discoverable by id and pulled on demand. `session.json` lists current failure summary only. Detailed locals, globals, fixtures, and runtime objects stay in the process and are inspected through PDB commands.

### Cost and Latency Budget

No model cost in library code. Latency budget is operational:

- session start overhead: near-zero unless feature enabled;
- no-client timeout: configurable, default short enough for CI safety;
- heartbeat lease: configurable renewal window;
- artifact writes: small Markdown/JSON only.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|-----------|--------------------------|---------------------|----------|
| Attach reliability | Pass if agent can discover session, connect to active failure, inspect current frame, and release test | Integration test with fake MCP client / subprocess | Critical |
| Timeout safety | Pass if no-client failure resumes pytest after configured timeout with no stale active session | Code + integration test | Critical |
| Heartbeat cleanup | Pass if missed heartbeat closes session and pytest continues; renewed heartbeat keeps hold alive | Code + integration test | Critical |
| Failure-state fidelity | 5 = nodeid, exception, stack, and BDD metadata all match failing test; 1 = any mismatch | Integration/BDD tests | Critical |
| Artifact validity | Pass if both Markdown and JSON are produced from validated schema and linked to failure | Code-based schema validation | High |
| Secure defaults | Pass if default host is local-only, docs warn about PDB code execution, and public bind is explicit | Static/config test + doc review | High |
| Dependency boundary | Pass if all `mcp-pdb` imports live in adapter module and no PDB/MCP command reimplementation appears elsewhere | Static architecture test | Medium |

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| Local-only host default | Feature enabled with no host configured | Bind `127.0.0.1` |
| Unsafe public bind warning | Host configured as `0.0.0.0` or non-local address | Emit explicit trusted-environment warning |
| No-client timeout | Active failure receives no MCP connection before timeout | Close debug hold and continue pytest |
| Heartbeat lease expiry | Connected agent misses lease renewal | Release/close session and continue pytest |
| Single active failure | Failure occurs while another failure is held | Queue behind active failure or report unsupported concurrency for v1 |
| Artifact schema validation | Agent artifact JSON fails Pydantic validation | Reject artifact and record validation error |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| Attach success rate | All debug-MCP integration runs | Investigate adapter/port/discovery failures |
| Timeout cleanup reliability | Timeout fixture runs in CI | Block merge on hang or stale session file |
| Metadata mismatch rate | BDD debug fixture set | Fix BDD adapter capture timing |
| Artifact usefulness | Human review of initial 12-reference dataset | Refine artifact schema/template |

## 7. Production Monitoring

**Tracing Tool:** Arize Phoenix default for external agent harnesses; pytest-bdd-ng itself writes structured local session/artifact files and does not require hosted tracing.

**Key Metrics to Track:**

- MCP session start success/failure
- attach latency from failure hold to client connection
- no-client timeout count
- heartbeat expiry count
- artifact validation failures

**Alert Thresholds:**
For CI or automated agent runs, fail the run if cleanup does not complete by timeout plus grace period, if session discovery JSON is invalid, or if artifact schema validation fails after agent claims completion.

**Smart Sampling Strategy:**
Review artifacts where agent released without finding, heartbeat expired, timeout fired, or BDD metadata was partially missing. Sample one successful attach path per release to guard against silent drift.
