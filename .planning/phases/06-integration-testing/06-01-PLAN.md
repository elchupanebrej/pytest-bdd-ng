## Phase 6 - Wave 0: Step Matching Priority Contract Tests

**Objective:** Establish contract-level integration tests for step matching priority — the core
deterministic resolution algorithm. Verifies that specific beats generic, explicit ordering is
preserved, and no import-order dependency exists across registries.

**Why this matters:** Step matching priority is the single most impactful behavior for users.
Ambiguous or import-order-dependent matching causes silent step substitution bugs that are
extremely hard to diagnose. The three-tier matcher (strict → unspecified → liberal) from
`StepDefinitionManager.Matcher` must be validated against real Gherkin scenarios, not just
unit-level mock invocations. Currently **zero** integration tests cover matching priority.

**Output:** Two test files in `tests/feature/`:
- `test_step_matching_priority.py` — core priority ordering tests
- `test_step_matching_ambiguous.py` — ambiguity detection and resolution tests
