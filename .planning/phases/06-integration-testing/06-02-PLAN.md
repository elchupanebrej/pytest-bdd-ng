## Phase 6 - Wave 0: Scenario Execution Lifecycle & Edge Cases

**Objective:** Integration tests for full scenario execution lifecycle — every `RunStage`
transition, hook invocation order, and edge cases including empty scenarios, malformed
Gherkin, unicode, data tables, and docstrings.

**Why this matters:** The execution lifecycle (`idle → scenario_setup → scenario_running →
step_running → scenario_running → scenario_teardown → finished`) is the backbone of pytest-bdd.
Gaps here mean silent state corruption, leaked state between scenarios, or crashes on unusual
but valid Gherkin. Currently tested only at the unit level (characterization tests); no
end-to-end integration tests cover the full lifecycle through the real pytest pipeline.

**Output:** Test files:
- `tests/feature/test_run_lifecycle_integration.py` — lifecycle transition coverage via hooks
- `tests/feature/test_scenario_execution_edge_cases.py` — empty, unicode, data tables, docstrings

<threat_model>
## Trust Boundaries

- Hook invocation order — Hooks are invoked via pytest's hook system; order depends on
  `tryfirst`/`trylast` and registration order. Tests must assert observed order, not assume.
- Parallel state leakage — Run object is stash-bound; xdist workers have separate
  configs. Test must verify isolation.
- Gherkin parser error handling — Malformed Gherkin should produce clear error, not
  silent pass or cryptic traceback.

## STRIDE Threat Register

| T-06-06 | Denial of Service | Large data tables overwhelm step parameter injection | mitigate | Test with realistic table sizes (≤20 rows) |
