# Plan 13-01: Implement cucumber_json_dispatcher Plugin Package

## Goal

Create the `cucumber_json_dispatcher` plugin package — a strictly additive third pytest11
entry point that reads both INI (`cucumber_json_path`) and CLI (`--cucumber-json`) options
and applies CLI-wins precedence by zeroing the INI cache before the INI backend reads it.

<action>
Create file `src/pytest_bdd/plugin/cucumber_json_dispatcher/entrypoint.py`:

Module-level hooks pattern (no singleton object). Functions:

1. `pytest_configure(config) -> None` decorated with `@pytest.hookimpl(tryfirst=True)`:
   - FIRST check: `if hasattr(config, "workerinput"): return`  (D-10 xdist worker guard)
   - Read INI value: `ini_value = config.getini(str(CucumberJsonDispatcher.Ini.PATH_OPTION))`
   - Safely read CLI value: `cli_option = getattr(config, "option", None)` then
     `cli_value = getattr(cli_option, str(CucumberJsonDispatcher.Cli.OPTION_ATTR), None)`
   - If both `ini_value` (truthy string) and `cli_value is not None` (CLI set):
     - Zero the INI cache silently (D-06 CLI wins, D-07 no warning):
       `config._inicache[str(CucumberJsonDispatcher.Ini.PATH_OPTION)] = ""`
   - (No registration of backends — both are always registered as pytest11 plugins)

2. No `pytest_addoption` function (dispatcher reads existing options, registers none)

3. No `pytest_unconfigure` function (zeroing _inicache needs no cleanup)

Imports required:
- `import pytest`
- `from .const import CucumberJsonDispatcher`

Docstring for the module:
"""Dispatcher entrypoint: bridges INI and CLI cucumber-json config with CLI-wins precedence."""
</action>
