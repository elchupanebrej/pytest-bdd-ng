**D-05 vs REQ-06 Resolution:**

D-05 ("Supplying live mode and NDJSON import inputs at the same time is a configuration conflict") means the two operational modes are mutually exclusive:
- **Live mode** = `--allure-cucumber-output <dir>` alone (no `--allure-cucumber-messages-in`). Plugin consumes `pytest_bdd_message` hooks from running scenarios.
- **Import mode** = `--allure-cucumber-output <dir> --allure-cucumber-messages-in <file>`. Plugin reads NDJSON from file, does NOT consume hooks.

REQ-06 requires import mode to work with both flags together. The conflict D-05 describes is that you cannot be in both modes simultaneously — the existing code already handles this by checking `self.messages_in` in `pytest_sessionfinish` and `pytest_collection_modifyitems`. No additional UsageError is needed; the mutual exclusion is behavioral (import mode skips collection and reads from file; live mode collects hooks and reads from self.envelopes).

**plugin.py — Rewire live mode (per D-01, D-06):**

Step 1. In `pytest_sessionfinish`, locate the `else` branch (current lines ~66-84) that reads from `final_messages_file_path`.

Step 2. Replace the `else` branch body with:
```python
from pytest_bdd.model.execution_message_adapter import ExecutionMessageAdapter

if projections:
    from pytest_bdd.plugin.allure_cucumber.adapter import convert_to_allure_commons
```

Step 3. Remove the `finally` block (current lines ~92-102) that cleans up `final_messages_file_path` — live mode no longer reads from a file, so there is no temp file to clean up.

Step 4. Remove the import of `_resolve_reporter_state` and `TransportService` from the `else` branch scope (they are file-first dependencies).

Step 5. Keep unchanged: the `if self.messages_in is not None` branch (NDJSON import mode, lines ~53-64), the worker skip (`hasattr(self.config, "workerinput")`), and the non-empty directory warning (per D-13).
