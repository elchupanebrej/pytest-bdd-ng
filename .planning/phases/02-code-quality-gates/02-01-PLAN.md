    1. Create directory `src/pytest_bdd/.ruff/rules/`

    2. Create `src/pytest_bdd/.ruff/rules/__init__.py` (empty file for package)

    3. Create `src/pytest_bdd/.ruff/rules/quality_gates.py` implementing a ruff plugin with two rules:

       Rule 1 — `PGH901` ("no-return-none-in-non-hook"):
       - AST visitor that detects `return None` statements in non-hook functions
       - Hook functions are identified by name pattern: starts with `pytest_` or `_pytest_` (per D-03 — pytest hook contract)
       - Functions whose name matches `pytest_*` or `_pytest_*` are EXEMPT from this rule
       - All other functions with `return None` trigger PGH901
       - Message: "PGH901: `return None` in non-hook function — use `Nothing` (Maybe) or `Failure(reason)` (Result) instead"

       Rule 2 — `PGH902` ("bare-except-without-logging"):
       - AST visitor that detects `except Exception:` (bare except) without `# noqa: PGH902` comment
       - The except block MUST contain either:
         a) `logger.warning(exc_info=True)` or `logger.exception(...)` call, OR
         b) `# noqa: PGH902` comment on the same line or the line above
       - Functions in per-file-ignores for BLE001 in pyproject.toml are NOT exempt — PGH902 is separate from BLE001
       - Message: "PGH902: bare `except Exception:` without logging — add `logger.warning(exc_info=True)` or `# noqa: PGH902`"

       Implement as a standard ruff plugin using `ruff.lint.Linter` registration:
       ```python
       # Use ruff's plugin API — register rules as standard linter rules
       # Detect return None by visiting ast.Return nodes
       # Detect except Exception by visiting ast.ExceptHandler nodes
       # Use ast.unparse or node inspection for type checking
       ```

    4. Register the rules in pyproject.toml:
       - Add `"PGH"` (pygrep-hooks namespace or custom prefix — use `PGH` as the rule prefix since it's already in the ruff select list) to `[tool.ruff.lint] select` (already present at line 342: `"PGH"`)
       - Actually, since `PGH` is already selected and is a built-in ruff rule namespace, use a different prefix. Use `"BLQ"` (BLock Quality) as the custom prefix.
       - Add `"BLQ"` to `[tool.ruff.lint] select` array

       Wait — ruff custom rules require a different registration. Use the ruff plugin mechanism:
       - Add `[tool.ruff.lint]` section:
         ```toml
         [tool.ruff.lint]
         extend-select = ["BLQ"]
         ```
       - But ruff doesn't support custom rule prefixes without plugin installation. Instead, implement as a standalone script that runs in CI as a separate check.

       **Revised approach (simpler, more reliable):**
       - Create a standalone script `src/pytest_bdd/.ruff/rules/quality_gates.py` that uses `ast` module (stdlib) to parse Python files and detect violations
       - Script is invoked as: `uv run python -m pytest_bdd._ruff.rules.quality_gates src/pytest_bdd/`
       - Returns exit code 1 if violations found, 0 if clean
       - Add to pre-commit config and CI as a separate step

       The script must:
       - Walk all `.py` files under src/pytest_bdd/
       - Parse each file with `ast.parse()`
       - Visit `ast.Return` nodes: if value is `ast.Constant(value=None)` and enclosing function name does NOT start with `pytest_` or `_pytest_`, flag it
       - Visit `ast.ExceptHandler` nodes: if `type` is `ast.Name(id='Exception')` and the handler body does NOT contain a `logger.warning/logging.warning` call with `exc_info=True` keyword, flag it unless `# noqa: BLQ902` is present
       - Print violations with `file:line: message` format
       - Exit 1 if any violations found, 0 otherwise
  </action>
